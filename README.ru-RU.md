# Portalis

[English](README.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru-RU.md)

## Обзор

Portalis — офлайн-менеджер пакетов с хеш-фиксацией для самостоятельно
собранных Linux-систем. Он собирает пакет из зафиксированного архива
исходников, сохраняет результат в неизменяемом хранилище пакетов и активирует
его через символические ссылки в рабочем дереве файловой системы. Каждая
установка записывает нумерованное generation, которое можно проверить или
откатить.

Пакеты хранятся в
`/usr/portalis/packages/<name>-<version>-<recipe-hash>/`. Рабочее дерево
содержит символические ссылки на эти каталоги, а не копии файлов.
`moirse rollback` восстанавливает набор пакетов предыдущего generation, а
`moirse --verify` сравнивает каждый активированный файл с записанным хешем.

Менеджер не обращается к сети и не устанавливает зависимости автоматически.
Параметры компиляции и сборки задаются recipe. Описание механизма приведено
ниже.

## Возможности

- Каждый пакет занимает отдельный каталог хранилища, имя которого содержит имя
  пакета, версию и хеш recipe и среды сборки. Одинаковые входные данные дают
  одинаковый путь хранилища.
- Рабочее дерево содержит символические ссылки на хранилище. Поэтому удаление,
  обновление или откат пакета не изменяет файлы, которые он предоставляет.
- Каждая установка записывает нумерованное generation. `moirse rollback <id>`
  восстанавливает набор пакетов предыдущего generation; необходимые для него
  хранилища сохраняются.
- Каждый активированный файл хешируется и записывается. `moirse --verify`
  сообщает об изменённом файле хранилища и завершается с ненулевым кодом при
  обнаружении проблемы.
- При наличии ключа подписи манифест сборки подписывается локальным ключом
  Ed25519 и проверяется по доверенным открытым ключам. При
  `security.require_signature = true` непроверяемый пакет отклоняется.
- Архивы исходников распаковываются под непривилегированной учётной записью.
  Шаги сборки выполняются в bubblewrap, если он доступен, иначе в Landlock; если
  недоступны оба механизма, используется только непривилегированная учётная
  запись. Запись ограничена деревом исходников, каталогом подготовки и
  каталогами, объявленными в recipe. Следующие каталоги хоста нельзя объявить
  доступными для записи: `/etc`, `/usr`, `/home`, `/root`, `/var`, `/boot`,
  `/proc`, `/sys`, `/dev`, `/bin`, `/sbin`, `/lib`, `/lib32`, `/lib64`,
  `/libx32`, `/run`, `/opt`, `/srv`, `/mnt`, `/media` и `/tmp`.
- Сборка получает доступ к сети только при `build.network = true` в recipe. Для
  офлайн-шага bubblewrap изолирует сеть, а резервный путь Landlock устанавливает
  фильтр seccomp, отклоняющий сокеты INET и INET6. В Landlock ABI 6 и новее
  также ограничиваются абстрактные UNIX-сокеты и сигналы; пространства имён PID,
  IPC и сети не создаются. Если активный механизм не может заблокировать сокеты,
  офлайн-шаг отклоняется.
- Шаги сборки ограничены по времени, адресному пространству, размеру файла и
  числу открытых файлов. Пустые значения конфигурации выбирают ограничения,
  производные от хоста сборки.
- Файлы, которые ещё отображаются в работающем процессе, не заменяются на
  месте. Транзакция откладывается и применяется при завершении работы.
- Скомпилированные двоичные и текстовые файлы переписываются так, чтобы пути
  хоста сборки не попадали в установленный пакет.

## Контейнер сборки

Сборка из исходников использует одноразовый контейнер. Если двоичный файл
содержит встроенный rootfs, Portalis распаковывает его один раз в
`/run/portalis/rootfs/<sha256>` или в `/var/lib/portalis/rootfs` при
постоянном кэшировании, после чего запускает bubblewrap со следующим
представлением.

- `/` — встроенный rootfs, включая статический BusyBox в `/busybox` и `/bin/sh`;
- каталоги инструментария хоста `/usr/bin`, `/usr/sbin`, `/usr/lib`,
  `/usr/lib32`, `/usr/lib64`, `/usr/libexec`, `/usr/include`, `/usr/share` и
  `/usr/local` монтируются только для чтения;
- `/etc` и `/usr/portalis` являются временными файловыми системами;
- `/usr/portalis/packages` монтируется только для чтения;
- хранилища зависимостей монтируются только для чтения в `/deps/<name>`;
- рабочий каталог и каталог подготовки доступны для записи;
- `/dev`, `/proc`, `/tmp` и `/dev/shm` являются новыми пространствами имён.

Шаги сборки выполняются от имени root в пространстве имён, при этом все
capability отбрасываются. Если bubblewrap недоступен, шаги выполняются с
uid/gid 65534 под Landlock. Без встроенного rootfs сборка использует
представление инструментария хоста только для чтения вместо встроенного
корня. Пути include, library, pkg-config, CMake и rpath добавляются из
объявленных хранилищ зависимостей. Обязанности компонентов приведены ниже.

### Ответственность компонентов

| Компонент | Ответственность |
| --- | --- |
| bubblewrap или Landlock | Обеспечивает изоляцию монтирования, процессов, сети и capability; не предоставляет userland или компилятор. |
| Встроенный rootfs | Предоставляет основу `/`, статический BusyBox и `/bin/sh`, минимальный userland и одноразовый корень для check. |
| Монтирования инструментария хоста | Предоставляют компилятор, компоновщик, заголовочные файлы, библиотеки и утилиты сборки; монтируются только для чтения. |
| Хранилища зависимостей | Предоставляют объявленные зависимости сборки в `/deps/<name>`; их пути include, library, pkg-config, CMake и rpath добавляются средой сборки. |
| Рабочий каталог и каталог подготовки | Предоставляют доступную для записи область сборки; встроенный rootfs и хранилище пакетов остаются доступными только для чтения. |
| Хранилище пакетов | Предоставляет неизменяемое хранилище пакетов, смонтированное только для чтения для разрешения зависимостей и изоляции сборки. |

## Механизм

1. `moirse install <archive>` разрешает recipe либо рассматривает архив как
   заранее собранный пакет, если подходящий recipe отсутствует.
2. Архив проверяется по зафиксированному значению в recipe, а путь хранилища
   выводится из recipe, ABI хоста, встроенного rootfs, хранилищ зависимостей и
   настроек изоляции.
3. Пакет из исходников распаковывается под непривилегированной учётной записью
   и собирается в описанном выше контейнере. Заранее собранный пакет пропускает
   шаги сборки.
4. Результат запечатывается в хранилище пакета вместе с манифестом и маркером
   завершения. Перед принятием хранилища проверяются пути, режимы, хеши и цели
   ссылок манифеста.
5. Активация сравнивает манифест с рабочим деревом, создаёт резервные копии
   принятых файлов, записывает ссылки на хранилище и фиксирует запись
   активации. Файлы, отображаемые работающим процессом, откладываются и
   применяются при завершении работы.
6. База состояния записывает пакет, его файлы и новое generation. Предыдущее
   generation остаётся доступным для `moirse rollback`.

`moirse --verify` сравнивает активированные файлы с записанными хешами, а
хранилища — с маркерами завершения. Подписанный манифест проверяется по
доверенным ключам; при `security.require_signature = true` непроверяемые пакеты
отклоняются. `moirse rollback <id>` восстанавливает generation без повторной
сборки хранилищ. Раздел механизма выше содержит описание терминов и процесса
восстановления.

## Установка

Официальный установщик — это shell-скрипт, размещённый в репозитории
выпусков. Он выбирает архив выпуска для архитектуры хоста, загружает архив
вместе с файлами `.sha256` и `.sig`, проверяет подпись Ed25519 и контрольную
сумму, распаковывает двоичный файл и устанавливает его. Запуск выполняется от
имени root:

```sh
curl -fsSL https://raw.githubusercontent.com/saves24/portalis/master/install.sh | sudo sh
```

Для установки конкретной версии передайте её скрипту:

```sh
curl -fsSL https://raw.githubusercontent.com/saves24/portalis/master/install.sh | sudo sh -s -- 0.1.0
```

Установщик размещает двоичный файл в `/usr/lib/portalis/portalis`, создаёт
символическую ссылку `/usr/bin/moirse`, создаёт каталоги состояния и
устанавливает модуль systemd `portalis.service`, применяющий отложенные
активации при завершении работы. При вызове с путём к локальному двоичному
файлу установщик принимает этот файл; в этом режиме архив выпуска не
загружается и не проверяется.

Архивы выпуска имеют формат `.tar.gz` и имя
`portalis-<version>-<target>.tar.gz`. Архив содержит:

```text
portalis          статический двоичный файл
install.sh        установщик
LICENSE           лицензия MIT
release.pub       открытый ключ выпуска
```

Открытый ключ, встроенный в `install.sh`, является якорем доверия для загрузки.
Файл `release.pub` внутри архива подходит для проверки внутренней
согласованности, но не является независимым якорем доверия. При необходимости
загруженный архив можно проверить вручную перед распаковкой.

Установщик поддерживает архивы выпусков для x86_64 и aarch64. Для других
архитектур требуется сборка из исходников. Официальные двоичные файлы выпусков
статически слинкованы и не зависят от системной библиотеки C; локально
собранный двоичный файл использует компоновку, созданную локальным
инструментарием.

### Зависимости установщика и среды выполнения

Установщику, загружающему выпуск, требуются `curl` или `wget`, `openssl`
(версия 3 для проверки Ed25519), `tar`, `gzip` и `sha256sum`. Менеджер также
использует `xz`, `zstd` или `bzip2`, если архив пакета применяет
соответствующий формат сжатия. `bubblewrap` необязателен; если он недоступен,
шаги сборки используют резервный путь Landlock, описанный выше. Если
недоступны и bubblewrap, и Landlock, шаги сборки выполняются только под
непривилегированной учётной записью, а офлайн-шаги отклоняются. Команде check
требуется `bubblewrap`; если `check.required` равно false и bubblewrap
недоступен, check пропускается с предупреждением.

Если установщик получает локальный двоичный файл, архив выпуска не
загружается; поэтому архив следует проверить перед распаковкой.

### Сборка из исходников

Дерево исходников использует инструментарий Rust, зафиксированный в
`rust-toolchain.toml`:

```sh
cargo build --release --locked
```

Команда создаёт локальный двоичный файл для хоста сборки. Образ rootfs
встраивается только при наличии `PORTALIS_ROOTFS_IMAGE` и
`image/manifest.toml` во время сборки. Официальные двоичные файлы выпусков
создаются процессом выпуска проекта и не идентичны локальной сборке без
соответствующей конфигурации.

## Команды

| Команда | Назначение |
| --- | --- |
| `moirse` | Список установленных пакетов |
| `moirse install <archive>` | Собрать и применить пакет из архива; при отсутствии recipe импортировать его |
| `moirse remove <package>` | Удалить ссылки пакета |
| `moirse remove <package> --purge` | Удалить ссылки и каталог хранилища пакета |
| `moirse remove <package> --pending` | Удалить только отложенную копию; установленная версия сохраняется |
| `moirse remove <package> --force` | Обойти отказ из-за зависимостей, занятых файлов или занятого хранилища |
| `moirse rollback <id>` | Восстановить набор пакетов из generation |
| `moirse clean [--logs] [--store] [--backups] [--yes]` | Удалить старые журналы, неиспользуемые хранилища, устаревшие деревья сборки и замещённые резервные копии |
| `moirse --show <package>` | Показать версию, размер, зависимости, зависимые пакеты и файлы одного пакета |
| `moirse --file <path>` | Определить пакет, которому принадлежит путь |
| `moirse --history` | Список снимков generation |
| `moirse --verify` | Сравнить каждый активированный файл с записанным хешем, а каждое хранилище — с маркером завершения |
| `moirse --check` | Разобрать все recipe и сообщить о некорректных |
| `moirse --orphans` | Сообщить о неиспользуемых и отсутствующих хранилищах и висячих ссылках |
| `moirse --logs <package> [--tail N]` | Показать журналы сборки или последние N строк новейшего журнала |
| `moirse --quiet` | Подавить строки прогресса длительной команды |
| `moirse --discard-recovery` | Удалить журнал activation или operation, блокирующий команды записи, и сообщить об удалённых путях |
| `moirse --version` | Показать версию и идентификатор встроенного rootfs, если он присутствует |

Флаги проверки `--show`, `--file`, `--history`, `--orphans`, `--verify`,
`--check` и `--logs` нельзя комбинировать с подкомандой. `--tail` требует
`--logs`. Команды записи требуют прав root. `clean` сначала выводит план и
ничего не удаляет без `--yes`.

`remove` отказывается работать, если другой установленный пакет зависит от
целевого пакета; `--force` отменяет эту проверку. `remove --purge` также
отказывается удалять хранилище, отображаемое работающим процессом; `--force`
отменяет эту проверку. Команды записи выполняют обслуживание: удаляют
устаревшие каталоги сборки старше одного часа и старые журналы сборки без
отдельного вызова `clean`.

## Recipe

Recipe — это текстовый файл, содержащий по одному выражению `key = value` в
строке. Ключи могут быть плоскими или точечными; `#` начинает комментарий;
списки разделяются запятыми; многострочные значения записываются между строкой
`<<MARKER` и закрывающей строкой `MARKER`.

```text
# build xkbcomp from a pinned archive
package.name = xkbcomp
package.version = 1.4.7
package.depends = xkeyboard-config, libxcb

source.file = xkbcomp-1.4.7.tar.xz
source.sha256 = 0a288114e5f44e31987042c79aecff1ffad53a8154b8ec971c24a69a80f81f77

build.system = autotools
build.args = --disable-static, --with-x
build.cflags = -O2 -pipe

install.prefix = /usr
files.preserve = /etc/xkbcomp.conf
hooks.ldconfig = true
check.command = xkbcomp --version
check.timeout = 300
```

### Ключи recipe

| Ключ | Значение |
| --- | --- |
| `package.name` | Имя пакета; обязательно |
| `package.version` | Версия пакета; обязательна |
| `package.description` | Читаемое описание; не входит в хеш recipe |
| `package.hold` | Запрещает удаление без `--force` |
| `package.depends` | Зависимости пакета через запятую |
| `source.kind` | `source` для сборки из исходников, `binary` для заранее собранного пакета |
| `source.file` | Имя архива; обязательно |
| `source.sha256` | SHA-256 архива исходников; обязателен |
| `source.dir` | Каталог внутри архива; определяется автоматически, если пуст |
| `build.system` | `autotools`, `meson`, `cargo` или `custom`; по умолчанию `autotools` |
| `build.args` | Аргументы сборки через запятую |
| `build.cflags` | Флаги компилятора C |
| `build.cxxflags` | Флаги компилятора C++ |
| `build.rustflags` | Флаги компилятора Rust |
| `build.isolation` | `rpath` добавляет пути хранилищ зависимостей в ELF runpath |
| `build.env.<NAME>` | Дополнительная переменная окружения для шагов сборки |
| `build.network` | Разрешает доступ к сети во время сборки |
| `build.writable` | Дополнительные пути хоста, монтируемые в песочнице для записи |
| `build.read` | Дополнительные пути хоста, монтируемые в песочнице только для чтения |
| `build.jobs` | Число параллельных задач сборки для recipe |
| `build.patch` | Встроенный блок патча; повторяется в порядке применения |
| `install.prefix` | Префикс установки; по умолчанию `/usr` |
| `install.setuid` | Пути, которым разрешено сохранять бит setuid |
| `install.setgid` | Записи `path:group`, которым разрешено сохранять бит setgid |
| `install.deps_ignore` | Относительные префиксы путей, ELF-файлы которых используют частный rpath |
| `files.preserve` | Пути конфигурации, копируемые один раз и не перезаписываемые |
| `hooks.ldconfig` | Запускать `ldconfig` после активации |
| `hooks.icon_cache` | Каталоги тем, для которых обновляется кеш значков |
| `hooks.daemon_reload` | Запускать `systemctl daemon-reload` после активации |
| `check.command` | Команда, выполняемая после сборки и до активации |
| `check.timeout` | Тайм-аут check в секундах; по умолчанию 300 |
| `check.required` | Отклонять установку при неудаче или невозможности check; по умолчанию `false` |

Значения обрезаются по краям. Одинарные или двойные кавычки сохраняют
начальные и конечные пробелы, запятые и символы `#`; внутри кавычек
распознаются `\n` и `\t`. Символ `#` вне кавычек начинает комментарий.
Неизвестные ключи отклоняются; ключ может повторяться только там, где это
разрешает формат, например `build.patch`. Команда `moirse --check` проверяет
все recipe в каталоге recipe.

### Аргументы сборки и патчи

`build.args` интерпретируется выбранной системой сборки. Для `autotools`
записи добавляются к `./configure`; для `meson` — к `meson setup`; для `cargo`
передаются в вызов cargo; для `custom` каждая запись выполняется отдельной
командой `sh -c` с экспортом `DESTDIR`, `PREFIX` и `SRCDIR`. Записи
разделяются запятыми и могут быть заключены в кавычки, если содержат запятую.
Поэтому команду с запятой можно заключить в кавычки или вынести в скрипт,
поставляемый в архиве.

Патч задаётся одним блоком; ключ повторяется для каждого патча в порядке
применения. Необязательное поле `optional = true` пропускает патч, который
больше не применяется:

```text
build.patch = <<PATCH
file = fix-openssl4.patch
sha256 = 9f2c...
content = <<DIFF
--- a/configure
+++ b/configure
@@ -1 +1 @@
-PKG_CHECK_MODULES(SSL, openssl)
+PKG_CHECK_MODULES(SSL, openssl >= 3.0)
DIFF
PATCH
```

### Поведение сборки и check

`check.command` выполняется после сборки и до активации внутри встроенного
rootfs, при этом пакет и его зависимости установлены в одноразовый корень.
Check не имеет доступа к файловой системе хоста и сети, не получает
capability и выполняется с uid 65534. Ненулевой код возврата по умолчанию
выводит предупреждение. `check.timeout` по умолчанию равен 300 секундам. При
`check.required = true` неудача или невозможность выполнения check отклоняет
установку. Сборка без встроенного rootfs или без bubblewrap пропускает check;
при `check.required = true` установка отклоняется.

Сборка из исходников сохраняет обычные режимы файлов. Биты setuid и setgid
сохраняются только для путей, объявленных в `install.setuid` и
`install.setgid`. Запись setgid должна указывать группу, которая разрешается в
`etc/group` целевого корня; запись без группы или с отсутствующей группой
отклоняет установку.

Заранее собранный пакет объявляет `source.kind = binary` и не содержит шагов
сборки. Архив без подходящего recipe импортируется как заранее собранный
пакет: имя и версия читаются из имени файла или из полей управления для
`.deb`. Архив, обёрнутый в один каталог верхнего уровня, отклоняется; корень
архива должен соответствовать корню файловой системы.

Импортированные архивы сохраняют обычные режимы файлов. Биты setuid или setgid
в импортированном архиве отклоняются, если при установке не задан
`PORTALIS_KEEP_PRIVILEGED=1`; при этом переопределении биты записываются в
производный recipe как `install.setuid` или `install.setgid`. Запись setgid
фиксирует группу из заголовка файла; при установке группа разрешается в
целевом корне, и пакет отклоняется, если группы нет.

Шаги сборки видят дерево исходников, представление инструментария только для
чтения и хранилища зависимостей, явно предоставленные метаданными пакета. Пути
include, library, pkg-config, CMake и rpath добавляются из этих хранилищ;
сборка, которой требуются дополнительные заголовки или библиотеки, должна
объявить соответствующую зависимость или предоставить собственные копии.

## Конфигурация

Необязательный файл конфигурации — `/etc/portalis/config.port`. Отсутствующие
ключи сохраняют значения по умолчанию.

```text
security.require_signature = true

maintenance.retain_generations = 5
maintenance.backup_retention_days = 30

build.scrub_paths = true

build.jobs = 4
build.limit_memory_mb = 4096
build.limit_file_mb = 2048
build.limit_cpu_seconds = 3600
build.limit_open_files = 1024

rootfs.cache = runtime
```

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `security.require_signature` | `false` | Отклонять manifest, который не проверяется доверенным ключом; это локальное доверие, а не происхождение пакета |
| `maintenance.retain_generations` | `5` | Число generation, сохраняемых до освобождения данных отката |
| `maintenance.backup_retention_days` | `30` | Срок хранения замещённых резервных копий |
| `build.scrub_paths` | `true` | Переписывать пути хоста сборки в файлах подготовки |
| `build.jobs` | не задано | Число параллельных задач; по умолчанию половина доступных ядер |
| `build.limit_memory_mb` | не задано | Ограничение адресного пространства в MiB; по умолчанию половина памяти хоста |
| `build.limit_file_mb` | не задано | Ограничение размера файла в MiB; по умолчанию половина свободного места рабочей области |
| `build.limit_cpu_seconds` | не задано | Ограничение процессорного времени; по умолчанию не задано |
| `build.limit_open_files` | не задано | Ограничение числа открытых файлов; по умолчанию половина жёсткого лимита |
| `rootfs.cache` | `runtime` | `runtime` или `tmpfs` для `/run`; `persistent` для `/var/lib/portalis/rootfs` |

Значение `0` снимает соответствующее ограничение ресурса. `build.jobs = 0`
выбирает число рабочих потоков по умолчанию. Каждый шаг сборки имеет отдельный
тайм-аут 3600 секунд, если `PORTALIS_BUILD_TIMEOUT` не задаёт другое
положительное значение. Некорректная конфигурация прерывает установку вместо
скрытого ослабления требований.

Изоляция выбирается в следующем порядке: bubblewrap, Landlock, затем только
непривилегированная учётная запись. `PORTALIS_NO_BWRAP=1` пропускает только
bubblewrap; Landlock остаётся активным, если доступен. На пути Landlock фильтр
seccomp блокирует сокеты INET и INET6 для офлайн-шагов. Ни один переключатель
не удаляет выбранный механизм. Если недоступны и bubblewrap, и Landlock,
офлайн-шаг отклоняется, поскольку процесс не может гарантировать блокировку
сокетов.

Хеш сборки включает активный механизм изоляции, отпечаток ABI хоста, дайджест
встроенного rootfs и пути хранилищ зависимостей. Поэтому один и тот же recipe
разрешается в другой путь хранилища при различии этих входных данных.
Параметр `PORTALIS_WIDE_READ` игнорируется для шагов сборки.

## Структура каталогов

| Путь | Содержимое |
| --- | --- |
| `/usr/portalis/packages/` | Хранилища пакетов |
| `/usr/portalis/etc/` | Экспортируемые деревья `etc` отдельных пакетов |
| `/usr/portalis/appconfig/` | Локальные параметры сборки пакетов |
| `/etc/portalis/packages/*.port` | Recipe |
| `/etc/portalis/config.port` | Параметры безопасности, обслуживания и сборки |
| `/etc/portalis/signing.key` | Локальный ключ подписи, если присутствует |
| `/etc/portalis/trusted-keys/` | Доверенные открытые ключи |
| `/var/db/portalis/db.sqlite` | База пакетов, файлов и generation |
| `/var/lib/portalis/` | Блокировка состояния, запись активации, отложенная транзакция, резервные копии и `last-good.json` |
| `/var/lib/portalis/backup/` | Резервные копии файлов хоста, заменённых транзакцией |
| `/var/lib/portalis/rootfs/` | Постоянный кеш rootfs при `rootfs.cache = persistent` |
| `/run/portalis/rootfs/` | Временный кеш rootfs при `rootfs.cache = runtime` или `tmpfs` |
| `/var/log/portalis/builds/` | Журналы сборки |
| `/etc/systemd/system/shutdown.target.wants/portalis.service` | Модуль, применяющий отложенные активации при завершении работы |

Путь хранилища учитывает recipe и среду, в которой выполнялась сборка. Другой
режим изоляции, ABI хоста, образ rootfs, набор зависимостей или настройка scrub
дают другой каталог.

## Эксплуатационные замечания

- Команды записи изменяют системные пути и должны выполняться от имени root.
  Перед записью можно выполнить
  `PORTALIS_DRY_RUN=1 moirse install <archive>`, чтобы получить список файлов,
  которые заменит транзакция.
- Перед активацией проверяется каждый путь манифеста. Необъявленные биты
  setuid или setgid и ссылки на защищённые расположения хоста, такие как
  `/home`, `/root`, `/proc`, `/sys` или `/dev`, отклоняются.
- Пакет принимается только при соответствии манифеста recipe и архиву. Если
  доверенные ключи не настроены, неподписанная сборка принимается с
  предупреждением; после установки доверенных ключей следует задать
  `security.require_signature = true`.
- Ключ подписи должен принадлежать root и быть доступным для чтения только
  владельцу (`chmod 600`); иначе подпись отклоняется.
- `security.require_signature` проверяет manifest по доверенным ключам. Ключ
  подписи является локальным: пакет, подписанный на этом хосте, доказывает
  только то, что хост обработал его. Это не подтверждает происхождение из
  внешнего источника. Для недоверенных источников следует использовать
  независимую подпись или отдельный канал проверки.
- Файлы, отображаемые работающим процессом, не заменяются на месте.
  Транзакция откладывается и применяется при завершении работы; `moirse` без
  аргументов сообщает об отложенных пакетах. Информация об использовании файла
  читается из `/proc`; если она недоступна, транзакция откладывается до
  завершения работы.
- После изменений в рабочей системе следует выполнять `moirse --verify`. Он
  сообщает об изменённых файлах хранилища, записях без строки пакета и
  незавершённых активациях; при обнаружении проблемы возвращается ненулевой
  код.
- `rollback` восстанавливает generation, но сохраняет каталоги хранилищ, поэтому
  откат не требует пересборки. `moirse clean --store` освобождает хранилища,
  на которые не ссылаются ни пакеты, ни сохраняемые generation.
- Импортированный без recipe архив записывает SHA-256 установленного payload.
  Для `.deb` это член payload, а не внешний архив. Хеш идентифицирует файл, но
  не аутентифицирует его. `security.require_signature` проверяет только
  локальные доверенные ключи и не подтверждает происхождение из внешнего
  источника.
- Импортированный архив с файлами setuid или setgid отклоняется, если не задан
  `PORTALIS_KEEP_PRIVILEGED=1`. Запись setgid фиксирует группу из заголовка
  файла; при установке группа разрешается в целевом корне, и пакет
  отклоняется, если группы нет.
- `--discard-recovery` удаляет журнал activation или operation, блокирующий
  команды записи, и сообщает об удалённых путях. Параметр предназначен для
  оператора, который проверил журнал и решил его отбросить; нормальное
  восстановление должно быть разрешено до завершения.
